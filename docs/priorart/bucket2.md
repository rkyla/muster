# Prior art — BUCKET 2: agent memory / coordination layers, git-aware MCP, AI code attribution

Surveyed 2026-10-12 with `priorart.py` (GitHub API, token via `gh auth token`). Every star count and date below was read back from `pa.repo()` on that date, not from a search snippet.

Capability shorthand for the overlap column: **(1)** observe refs/worktrees/dirty files by git plumbing without the agent cooperating; **(2)** attribute edits to a session/agent/branch; **(3)** file-level AND hunk/line-range collision prediction *before* a merge; **(4)** grounded brief of functionality being built elsewhere; **(5)** integration orchestration (isolated-worktree merge plans, splitting one mixed dirty tree into per-feature branches).

Bucket label key: **(a)** long-term memory of past decisions, **(b)** task/queue coordination, **(c)** live concurrent-edit awareness.

The bucket spans five sub-areas, so the table runs to 26 rows; tools with no overlap are listed as terse controls after the table rather than as rows.

## The bucket question: does anything already give an agent grounded awareness of what OTHER sessions are editing RIGHT NOW?

Short answer: **the (c) category exists and is crowded, but every tool found is either cooperative/self-reported or claim-based. None of them derives the live edit map from git plumbing alone, and none of them predicts overlap at hunk/line-range level inside one shared dirty working tree.**

The three categories in the wild:
1. **(a) long-term memory of past decisions** — huge and mature: claude-mem (~99.7k), mem0 (~67k), Letta/MemGPT (~25k), Basic Memory (~4.1k), mnemon, memoripy, understory, okf-agent-memory, memento, AgentDB, keep-the-why, director, aictx. They persist *narrative* state across sessions. None indexes the current working tree, none knows a second session exists. Overlap with us: **none**, except Atlas and brain0, which attribute *commits* to sessions after the fact.
2. **(b) task/queue coordination** — also crowded: Beads (~27.8k), mcp_agent_mail (~2.2k), teammcp, llm-bus, tl, baton, agent-comms, gittub, orchestune, Watchbill, dibs claims, agentsync. These divide work and hand it over. They answer "what should I do / what did you decide", not "what is being edited under my hands right now".
3. **(c) live concurrent-edit awareness** — the real collision zone, and it is young (all created 2026, all but one under 10 stars).

Closest (c) examples, in order of threat:

| 2 | **Beacon** | each session's hook reports its own edits to a local daemon | file + risky-git-op guard | **yes** | ~4 |
| 3 | **Traffic Control** | agents take clearances on paths from a daemon "tower" | path/glob, warn or block | **yes** | ~2 |
| 4 | **SAGE** | hybrid: touched globs read from git + voluntary claims | glob, plus a merge-brief | board is per checkout | ~4 |
| 5 | **git-sync-check** | `git status` pre-flight, classifies foreign uncommitted files | file, advisory only | **yes** | ~5 |
| 6 | **Hivemind** | symbol-level claims enforced by hook/daemon | function/symbol | no — CRDT sync between trees | ~1 |
| 7 | **Foremerge** | voluntary intent declarations, deterministic detector | symbol/scope, cross-file intent | no — assumes worktrees | ~538 |

So the honest framing for the README: **live cross-session awareness is not novel — it is a recognised gap that at least a dozen small tools attacked during 2026.** What none of them does is our specific combination: derive the map from git plumbing only (no hooks, no daemon, no cooperating agent, so a session that installed nothing is still visible), attribute existing dirty files to a session/branch, predict overlap at hunk/line-range level *before* a merge, and then split one mixed dirty tree into per-feature branches. The dirty-tree→per-feature-branch split in particular returned **zero** hits in GitHub search across several phrasings and appears genuinely unclaimed.

## Surprises / collisions

1. **The premise is no longer ours alone.** Twelve-plus tools created in 2026 open with exactly our sentence — "agents are flying blind", "your agent does not know that someone else's agent is rewriting the same function right now" (AgentColab), "Agents are flying blind. **They can't see each other.**" (Beacon), "an agent cannot see what its peers are doing" (dibs). Several target the *same* scenario we claim: one shared working tree, not one worktree per agent — Traffic Control, Beacon, fencepost, agent-lock, wombat-gate, git-commit-lock, shared-tree-guards, Watchbill. We must not write the README as if we identified the problem.
2. **AgentColab is the sharpest conceptual collision.** It publishes, on a heartbeat, the files a session has *actually* touched derived from `git diff` against the merge base — git-derived, not self-reported — and warns the editing agent once, naming the other agent, their branch and their stated intent, then lets the repeat edit through ("Nothing is ever locked"). That is our capabilities (1)+(2)+(3-file-level) in one tool. It is also 0 stars and 6 weeks old, and it is per-branch, so it still cannot see two agents dirtying one tree.
3. **SAGE already separates "git fact" from "intent" and already prints a brief.** Its README table labels `touched_globs` as "Paths the checkout has dirtied (git fact)" and `sage merge-brief` prints contested paths / "clear to merge". Our grounding argument ("code extracts the facts so an LLM cannot invent them") has to be pitched against this, not against nothing.
4. **"No daemon, stdlib-only, local-only" is not a differentiator on its own.** dibs ships one static binary with no server and no DB; fencepost's core imports nothing outside `node:*` and has no daemon; Watchbill is markdown + git with "no server, no database, no vendor"; AgentColab claims zero dependencies and no server; SAGE has zero npm dependencies; git-sync-check is plain bash/PowerShell. Our stdlib-only Python is a tie, not a win. The defensible property is *observation without agent cooperation* (hooks/claims are the weak point of every tool above).
5. **git-ai owns the attribution format.** ~2.8k stars, an open standard for AI attribution carried in **git notes**, and adoption listed across Claude Code, Codex, Cursor, Copilot, OpenCode, Windsurf, Devin, Amp, Gemini. If we stamp which agent wrote a hunk we should write git notes compatible with that standard. Note also the counter-current (`no-ai-attribution`, `assisted-by`, `no-claude-coauthor`, `commit-cleaner-hook`): a visible group of users actively strips agent attribution, which limits how much a "who wrote this" feature can be leaned on.
6. **The vendor knows.** Traffic Control quotes Claude Code's own agent-teams documentation: "Two teammates editing the same file leads to overwrites. Break the work so each teammate owns a different set of files." Anthropic ships shared tree + task list + mailbox and leaves collisions to the user. Our tool has to be positioned as the observation/enforcement layer the vendor declined to build, and we should say plainly that a vendor feature could land on top of us at any time.
7. **Scale is reachable in this space.** Beads (agent issue tracker in git) ~27.8k, mcp_agent_mail ~2.2k, Atlas ~9.6k, claude-mem ~99.7k, git-ai ~2.8k — all created 2025-2026. A well-framed bucket-2 tool can get traction fast, which also means the (c) niche will keep getting more crowded.
